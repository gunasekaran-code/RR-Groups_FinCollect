# FinCollect — Flutter Frontend

Loan & Collection app, Flutter frontend only (no backend calls wired yet). White + gold theme.

## Setup

This package only contains `lib/` + `pubspec.yaml` — no `android/`/`ios/` platform folders,
since those need to be generated by your local Flutter SDK.

```bash
flutter create fincollect_app
cd fincollect_app
# then copy this lib/ folder and pubspec.yaml into it, overwriting the defaults
flutter pub get
flutter run
```

## Role → access mapping

- **Owner**: everything, including User Management and Settings. Also gets a
  "Admin page access" panel (on the User Management screen) with toggles to
  show/hide Chit Groups, Reports, and Settings for the Admin role — this is
  in-memory only for now (`lib/services/privilege_service.dart`); wire it to
  your backend to persist it.
- **Admin**: same sidebar as Owner minus User Management, filtered further by
  whatever the Owner has toggled on/off.
- **Agent**: Dashboard, Customers, Loans, Repayment Schedule, Collections,
  Overdue, Route Map, Notifications. No Chit Groups / Reports / Settings /
  User Management.
- **Bottom nav bar** is identical for every role: Dashboard, Customers,
  Loans, Repayment, Collections.

## Structure

```
lib/
  main.dart                 # routes + role guards
  theme/app_theme.dart       # white & gold design tokens (AppColors, AppTheme)
  models/                    # UserRole enum, AppUser
  services/
    session_service.dart     # static demo auth (singleton, like ApiService)
    privilege_service.dart   # Owner's admin-page toggles
  routes/app_routes.dart     # route name constants
  widgets/
    app_shell.dart           # shared Scaffold (AppBar + Drawer + BottomNav)
    app_drawer.dart          # role-based sidebar
    app_bottom_nav.dart      # fixed 5-tab bottom nav
    stat_card.dart, status_badge.dart, list_item_card.dart,
    search_filter_bar.dart, empty_state.dart
  screens/
    auth/login_screen.dart
    dashboard/dashboard_screen.dart
    customers/, loans/, repayment/, collections/, overdue/
    route_map/                (Agent only)
    chit_groups/, reports/    (Owner + Admin)
    notifications/
    user_management/          (Owner only)
    settings/                 (Owner + Admin)
```

Each page is its own file/route (`/dashboard`, `/customers`, `/loans`, `/repayment`,
`/collections`, `/overdue`, `/route-map`, `/chit-groups`, `/reports`,
`/notifications`, `/user-management`, `/settings`) so wiring a real backend
later is a matter of swapping the static `Map<String, String>` lists in each
screen for real API calls — same `Map<String, dynamic>` + normalization-helper
pattern used in the wss-ecommerce app.
